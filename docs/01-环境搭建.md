# 01 · 环境搭建

从一台什么都没装的 Windows，到能在游戏里跑自己写的卫月插件。

---

## 1. 装什么

| 东西 | 版本 | 备注 |
|---|---|---|
| .NET SDK | **8.0 或更高** | 必须是 SDK 不是 Runtime。`dotnet --version` 应 ≥ 8.0.100 |
| IDE | VS2022 / Rider / VSCode | VS 装的时候勾「.NET 桌面开发」工作负载 |
| Git | 任意 | 拉模板、管源码 |
| 卫月启动器 + FF14 客户端 | 国服 | 启动器会把 Dalamud 一起装好 |

> Dalamud 插件的目标框架是 `net8.0-windows`，平台 `x64`。
> FF14 客户端是 64 位 dx11，别用 AnyCPU。

### 验证 .NET SDK

```powershell
dotnet --list-sdks
# 应看到 8.0.xxx 或更高
```

---

## 2. 先跑通官方模板（别跳过）

在碰 SimpleACR 之前，先用官方 SamplePlugin 确认工具链是通的。
这一步能帮你把"环境问题"和"代码问题"分开。

```bash
git clone https://github.com/goatcorp/SamplePlugin.git MyFirstPlugin
cd MyFirstPlugin
dotnet build
```

看到 `Build succeeded. 0 Warning(s) 0 Error(s)` 就对了。

如果报错说找不到 Dalamud 类型，99% 是 `DalamudLibPath` 指错了 —— 见第 4 节。

---

## 3. 让插件在游戏里跑起来

### 3.1 打开 Dev 插件加载

```
游戏内输入 /xlsettings
  → 实验性（Experimental）
  → 勾选 "启用 DevPlugin 加载"
  → DevPlugins 区域 → 添加 → 浏览到你的 bin\Debug\
```

路径示例：
```
E:\Code\SimpleACR\SimpleACR\bin\Debug\
```

### 3.2 加载

```
/xlplugins → Dev Plugins 标签页 → 找到你的插件 → Load
```

看不到？检查：
- 目录里有 `SimpleACR.dll` **和** `SimpleACR.json`（清单）
- 清单的 `InternalName` 和 DLL 文件名一致
- `/xllog` 里搜插件名，看具体报错

### 3.3 热重载（开发期最重要的一环）

```
1. /xlplugins → 你的插件 → Unload
2. dotnet build
3. /xlplugins → 你的插件 → Load
```

不用重启游戏。**前提是 `Dispose()` 写对了** —— 所有 `+=` 的事件都要 `-=` 回去。
没写干净的表现是：卸载了，但功能还在跑，而且再加载一次就跑两份。

## 4. DalamudLibPath

IDE 靠这个路径找到 `Dalamud.dll` 等引用程序集。

| 环境 | 默认路径 |
|---|---|
| 国际服 XIVLauncher | `%AppData%\XIVLauncher\addon\Hooks\dev\` |
| 国服卫月 | 卫月安装目录下的 `addon\Hooks\dev\` |

> 这个目录是 Dalamud **第一次成功注入后**才创建的。
> 从来没启动过游戏 → 目录不存在 → IDE 报一堆"找不到 Dalamud"。

用 `Dalamud.NET.Sdk` 时这事儿 SDK 自己处理了；
用手工引用模式时写在 csproj 里：

```xml
<DalamudLibPath>C:\你的路径\addon\Hooks\dev\</DalamudLibPath>
```

## 5. 调试

### 5.1 附加到进程（最有用）

**Visual Studio**
```
调试 → 附加到进程 → 找 ffxiv_dx11.exe → 附加
```

**Rider**
```
Run → Attach to Process → 搜 ffxiv_dx11 → Attach with .NET Core Debugger
```

然后就能打断点、看变量、单步走循环逻辑。

> 必须用 **Debug 构建**。Release 会被优化，断点对不上行。

### 5.2 日志

```csharp
Service.Log.Information("...");
Service.Log.Debug($"GCD={st.GcdRemaining}");
```

看日志：
```
/xllog
```
或文件 `%AppData%\XIVLauncher\dalamud.log`（国服在卫月目录下）。

插件日志条目前面会带 `[SimpleACR]`，方便过滤。

### 5.3 往聊天框输出（最快）

```csharp
Service.ChatGui.Print($"[调试] GCD={st.GcdRemaining:F2}s");
```

不用切窗口，打木人的时候看得很直观。SimpleACR 的 `/sacr dump` 就是干这个的。

## 6. 常见报错

| 报错 | 原因 / 解法 |
|---|---|
| 一堆 `Dalamud` 类型找不到 | `DalamudLibPath` 错了，或者从没启动过游戏 |
| 编译报 `API level 不匹配` | `Dalamud.NET.Sdk` 版本太高，调低（国服常见） |
| 插件在列表里但 Load 失败 | 看 `/xllog`。通常是构造函数里注入了不存在的服务，或清单 `InternalName` 不匹配 |
| 类型在运行时是 null | 有些服务/数据在登录完成前不可用，**用之前判 null** |
| `unsafe` 相关报错 | csproj 里加 `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>` |
| 卸载后功能还在跑 | `Dispose()` 漏了 `-=` |
| 游戏崩溃 | 大概率在 hook 里抛异常。SimpleACR 没用 hook，但引擎外层仍包了 try/catch |

## 7. 推荐的目录安排

```
E:\Code\FF14Plugins\
├── SimpleACR\          ← 本项目的插件
├── Dalamud\            ← git clone 一份 Dalamud 源码，用来查 API 实现
└── FFXIVClientStructs\ ← git clone 一份，用来查结构体和函数签名
```

编译不过又不知道某个方法签名是什么的时候，直接在这两个仓库里搜，
比翻文档快得多。
