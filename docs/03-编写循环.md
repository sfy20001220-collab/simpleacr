# 03 · 编写循环

循环 DSL 手册 + 坦克循环的设计思路 + 从 AE 的 ACR 迁移过来要注意什么。

---

## 1. DSL 手册

一份循环 = 一个继承 `Rotation` 的类，在 `Build()` 里按**优先级从高到低**排技能。

```csharp
[Rotation("循环名", Job.XXX, Author = "你", Patch = "7.x")]
public sealed class MyRotation : Rotation
{
    public override void Build(RotationBuilder b)
    {
        b.Gcd("名字", actionId, 条件, 目标);
        b.Ogcd(...);
        b.Defensive(...);
    }
}
```

### 1.1 四个添加方法

| 方法 | 类别 | 节奏闸门 | 用途 |
|---|---|---|---|
| `b.Gcd(name, id, cond?, target?)` | `Gcd` | GCD 转好 + 不在咏唱 | 战技 / 魔法 |
| `b.Ogcd(name, id, cond?, target?)` | `Ogcd` | `CanWeave()` | 能力技 |
| `b.Defensive(name, id, cond?, target?)` | `Defensive` | `CanWeave()` + 独立开关 | 减伤 / 自保 |
| `b.Utility(name, id, cond?, target?)` | `Utility` | `CanWeave()` | 打断 / 驱散 / 位移 |

`Defensive` 受设置里的「启用减伤 / 自保条目」独立控制 —— 想验证纯输出循环时
把它一关就干净了。

### 1.2 目标选择（`TargetSlot`）

| 值 | 含义 |
|---|---|
| `Target`（默认） | 当前选中的目标；没目标时退回自己 |
| `Self` | 自己（`0xE0000000`）。buff 类必填 |
| `LowestHpParty` | 小队里 HP% 最低的人。写治疗 / 保护技能用 |
| `NearestEnemy` | 最近的敌人 |
| `Focus` | 焦点目标 |

### 1.3 条件

类型是 `Func<CombatState, bool>?`。传 `null` 表示无条件 ——
**无条件条目应该只出现在循环表最后，当兜底用。**

## 2. 条件库全表

### Buff / Debuff

```csharp
s.HasBuff(statusId)                    // 有 buff（剩余 > 0）
s.HasBuff(statusId, 3f)                // 有 buff 且剩余 > 3 秒
s.BuffRemaining(statusId)              // 剩余秒数，没有则 0
s.BuffStacks(statusId)                 // 层数

s.TargetHasDebuff(statusId)            // 目标有 debuff
s.TargetDebuffRemaining(statusId)      // 剩余秒数（补 DoT 用）
```

### 技能状态

```csharp
s.Cd(actionId)                         // 剩余冷却秒数（不含 GCD）
s.OffCooldown(actionId)                // 冷却好了吗
s.Charges(actionId)                    // 当前充能层数
s.OffCooldown(1234) && s.Charges(1234) >= 2
```

### 连招

```csharp
s.ComboStep(actionId)                  // 上一步打的是不是它
s.ComboStep(a, b, c)                   // 上一步是其中任意一个
s.InComboWindow                        // 连招窗口还开着吗（一般 30s）
s.ComboAction                          // 上一步的实际 ID
s.ComboTimer                           // 连招剩余时间
```

> **用游戏自己的连招状态，别自己记计数器。**
> 游戏记得清清楚楚，还能正确处理「被打断 / 切目标 / 超时」这些边界情况。
> 自己记的话这些情况全是 bug。

### 节奏

```csharp
s.GcdTotal / s.GcdRemaining / s.GcdRolling
s.CanWeave()                           // 现在能插能力技吗
s.IsCasting / s.CastRemaining
s.IsMoving / s.MoveSpeed
```

### 资源

```csharp
s.Mp / s.MaxMp / s.MpPercent
s.Hp / s.MaxHp / s.HpPercent
s.BeastGauge      // 战士：兽魂 0~100
s.OathGauge       // 骑士：忠义 0~100
```

> 其他职业的量谱要在 `CombatState.ReadGauge` 里加一个分支。
> 照着现有的 `Beast` / `Oath` 抄即可，同样是套在 try/catch 里。

### 目标与场面

```csharp
s.HasTarget / s.Target / s.TargetId
s.TargetDistance                       // 米
s.TargetHpPercent
s.EnemyCount(5f)                       // 5 米内敌人数（AOE 判定）
s.Enemies(25f)                         // 敌人列表（按距离从近到远）
s.NearestEnemy(25f)
s.PartyMinHpPercent()                  // 小队最低 HP%（不在队伍时 = 自己）
s.LowestHpPartyMember()
```

### 状态

```csharp
s.InCombat / s.InDuty / s.IsMounted
s.JobId / s.Level                      // 等级门槛用这个
```

## 3. 排优先级的三条原则

### 原则一：窗口限定的排最前

"错过就没有了"的优先于"随时能补的"。

- 安魂期间的告白连 → 排最前（安魂一结束就打不了了）
- 原初的解放期间的免费裂石 → 排最前
- 普通连招 → 排最后（随时能补）

### 原则二：资源优先于填充

资源会溢出，溢出 = 实打实的亏损；连招是填充，随时可以补。

这就是战士循环里 `裂石飞环`（耗兽魂）排在连招前面的原因：

```csharp
b.Gcd("裂石飞环", A.FellCleave,  s => s.HasBuff(S.InnerRelease) || s.BeastGauge >= 50);
b.Gcd("暴风碎",   A.StormsPath,  s => s.ComboStep(A.Maim));        // 填充，排后面
```

### 原则三：最后一条必须是无条件兜底

否则会出现"所有条件都不成立 → 这一帧什么都不按"，动作看起来一顿一顿的。

```csharp
b.Gcd("重殴", A.HeavySwing);   // 无条件的连招起手，兜底
```

## 4. 坦克循环的设计思路

（以 `WarriorRotation.cs` 为例，骑士同理）

### 4.1 分层

```
第一层：爆发窗口     解放 / 狂暴 —— 开窗口
第二层：资源消耗     裂石飞环 / 地毁人亡 —— 花兽魂
第三层：能力技       动乱 / 激怒 / 猛攻 —— 卡 CD
第四层：填充连招     重殴 → 凶残裂 → 暴风碎
第五层：远程开怪     飞斧（够不着时）
第六层：减伤自保     血气 < 复仇 < 战栗 < 泰然 < 摆脱 < 死斗
```

### 4.2 减伤的排法

**从弱到强**，因为引擎是命中即止 ——
如果死斗（8s 无敌）排第一，血量一低就开，后面那些永远轮不到。

```csharp
b.Defensive("血气",     A.Bloodwhetting,  s => s.HpPercent < 85f, TargetSlot.Self);
b.Defensive("复仇",     A.Vengeance,      s => s.HpPercent < 70f, TargetSlot.Self);
b.Defensive("战栗",     A.ThrillOfBattle, s => s.HpPercent < 55f, TargetSlot.Self);
b.Defensive("泰然自若", A.Equilibrium,    s => s.HpPercent < 50f, TargetSlot.Self);
b.Defensive("死斗",     A.Holmgang,       s => s.HpPercent < 12f && s.InDuty, TargetSlot.Self);
```

> 真实场景里减伤应该**预判**机制而不是看血量，
> 那需要时间轴（AE 的强项）。这里的血量阈值版本只是能跑的简化版 ——
> 打小怪够用，打零式远远不够。

### 4.3 位移技能留一层

```csharp
b.Ogcd("猛攻", A.Onslaught, s => s.Charges(A.Onslaught) >= 2);
```

留 1 层保位移。全打光的后果是需要跑机制时没技能可用。

## 5. 从 AE 的 ACR 迁移

如果你手上有 AE 的 ACR 脚本（或者记得它的逻辑），迁移套路是：

| AE 里的概念 | SimpleACR 里 |
|---|---|
| ACR 文件 | 一个 `Rotation` 子类 |
| 一行「条件 → 技能」 | `b.Gcd/Ogcd(name, id, cond)` |
| 内置函数 `GetSpell()` | `ActionIds` 常量表 |
| `HasBuff(id)` | `s.HasBuff(id)` |
| `CanUse(id)` | `s.OffCooldown(id)`（+ 引擎自动做的 `GetActionStatus`） |
| 时间轴 | ❌ 本项目没有，需要自己加 |
| 自动走位 | ❌ 需要 vnavmesh |

迁移时最容易踩的坑：**AE 的条件函数语义和这里不完全一致**。
比如 AE 的 `CanUse` 往往已经包含了"目标合法""在射程内"，
而本项目的 `s.OffCooldown` 只查冷却，其余交给引擎的 `GetActionStatus` 兜底。
照着语义改一遍，别直接照搬。

## 6. 新循环的自检清单

写完一份循环，按顺序过一遍：

- [ ] `dotnet build` 通过
- [ ] 进游戏，主窗口底部**没有**该循环的启动校验警告（否则有 ID 不存在）
- [ ] `/sacr find` 核对过所有新引用的技能 ID
- [ ] 循环表最后一条是无条件兜底
- [ ] 减伤条目从弱到强排列
- [ ] 位移类技能留了层数
- [ ] 打木人：`/sacr on`，看主窗口的「循环明细」命中次数分布是否合理
- [ ] 关掉「启用能力技」，纯 GCD 循环也应该能顺畅跑完
- [ ] `/sacr dump` 看一眼量谱 / buff 数据是不是真的读到了
  （量谱一直是 0 → `ReadGauge` 的字段名在你的版本上不对）

## 7. 一个完整的最小例子

```csharp
using SimpleACR.Core;
using SimpleACR.Data;

namespace SimpleACR.Rotations.Jobs;

// 假设我们给「某个职业」写一份三件套循环
[Rotation("示例·最小循环", Job.WAR, Author = "你", Patch = "7.x")]
public sealed class MinimalExample : Rotation
{
    public override void Build(RotationBuilder b)
    {
        // 1) 窗口限定：解放期间免费裂石，最高优先级
        b.Gcd("裂石飞环（解放中）",
            ActionIds.War.FellCleave,
            s => s.HasBuff(StatusIds.War.InnerRelease));

        // 2) 开窗口
        b.Ogcd("原初的解放",
            ActionIds.War.InnerRelease,
            s => s.HasTarget && s.OffCooldown(ActionIds.War.InnerRelease));

        // 3) 资源不溢出：兽魂满了就花掉
        b.Gcd("裂石飞环（兽魂 ≥ 50）",
            ActionIds.War.FellCleave,
            s => s.BeastGauge >= 50);

        // 4) 能力技
        b.Ogcd("动乱",
            ActionIds.War.Upheaval,
            s => s.HasTarget && s.OffCooldown(ActionIds.War.Upheaval));

        // 5) 填充连招（注意顺序：第三段在前，起手在后）
        b.Gcd("暴风碎", ActionIds.War.StormsPath, s => s.ComboStep(ActionIds.War.Maim));
        b.Gcd("凶残裂", ActionIds.War.Maim,       s => s.ComboStep(ActionIds.War.HeavySwing));
        b.Gcd("重殴",   ActionIds.War.HeavySwing);   // 无条件兜底

        // 6) 减伤（从弱到强）
        b.Defensive("血气", ActionIds.War.Bloodwhetting, s => s.HpPercent < 85f, TargetSlot.Self);
        b.Defensive("死斗", ActionIds.War.Holmgang,      s => s.HpPercent < 12f && s.InDuty, TargetSlot.Self);
    }
}
```

注意第 5 组：**连招是从后往前排的**。
因为"暴风碎"的条件是"上一步打完凶残裂"，它必须先被问到；
如果反过来排，起手技（无条件）会永远先命中，连招就永远停在第一步。

**这是写连招时最常见的错误。**
